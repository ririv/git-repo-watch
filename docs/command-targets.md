# 命令目标绑定

## 命令与视图的职责

每个命令动作通过 `Action::requirement` 声明所需的目标。全局动作声明 `Global`，例如打开任务页或设置。需要操作对象的动作声明仓库、文件路径、差异选区等目标。选项菜单及其选项也各自对应动作，使用同一套声明。

视图根据当前焦点和选中项提供具体目标。选择文件和打开文件是同一种目标的两个来源。例如在文件列表选中 `src/main.rs`，和在差异预览查看这个文件，都能提供工作区的 `src/main.rs`。同一个场景可以同时提供仓库、文件和差异选区。

命令前缀负责分组和补全。例如 `/repo diff` 仍是差异命令的分组，输入完整命令时也会核对目标。命令作者只需说明需要什么，提供方负责从当前视图提取目标。

## 目标示例

| 目标 | 提供方 | 使用方 |
| --- | --- | --- |
| 仓库 | 首页选中的仓库，或仓库内视图所属的仓库 | `/repo fetch`、`/repo sync` |
| 工作区文件或目录 | 文件树当前条目、变更列表当前条目、文件预览 | `/editor`、`/copy path` |
| 历史文件 | 提交或贮藏中的选中文件、正在阅读的文件差异 | `/copy path` |
| 工作区变更文件 | 工作区文件列表中当前组的已勾选文件，无勾选时取当前高亮文件 | `/repo diff discard-file` |
| 差异选区 | 聚焦普通工作区差异时的预览快照与所选块或行 | `/repo diff select`、`/repo diff discard` |
| 索引选区 | 文件列表里的文件，或差异预览中的块或行 | `/repo diff stage`、`/repo diff unstage` |
| 提交选区 | 提交历史选中的提交及批量选择 | Cherry-pick、Revert |

历史文件保留所属对象 ID 和仓库相对路径，只作为只读文件目标。`/copy path` 复制相对路径。`/copy` 根据当前内容复制，例如在差异预览复制补丁。

工作区使用 `/repo diff` 进入，通过 `/repo diff unstaged` 或 `/repo diff staged` 打开对应子视图。两个子视图分别保留光标、滚动位置和勾选。Ctrl+A 只勾选当前子视图的可见文件。暂存和取消暂存分别使用 `/repo diff stage` 和 `/repo diff unstage`。文件列表按文件操作，普通差异预览按块或行操作。冲突由独立的冲突处理流程管理。命令菜单显示所选文件或行的数量。未暂存差异选区使用 `/repo diff discard`，整文件使用 `/repo diff discard-file`。确认页分别列出从暂存区恢复的已跟踪文件和将永久删除的未跟踪文件。

## 操作上下文与目标结果

`Requirement` 是命令的目标需求；`CommandContext` 是当前操作上下文，由当前视图、焦点、仓库路径和命令草稿捕获的选择共同构成。现有 `command::Context` 只负责命令前缀和分组，两者职责独立。页面和流程仍由 `Mode` 管理。

目标解析结果统一使用和类型：

```rust
enum Target<T> {
    OutOfScope(Reason),
    Unavailable(Reason),
    Ready(T),
}
```

`Ready(T)` 携带具体的仓库、文件、差异选区、历史列表或其它能力。原来的独立 `Status` 已移除。各提供方分别解析仓库与内容、工作区、历史目标，公共上下文按 `Action::requirement` 组合它们，并在同一次解析中检查动作条件。空历史列表仍是一个真实目标；依赖选中提交的动作在其中暂时不可用。

流程为 `Requirement → CommandContext → Target<Resolved>`。`resolve_command` 在入口统一应用功能开关，再返回带具体对象的结果。菜单每一项的状态、说明和目标数量来自同一次解析；只需要判断可见性的调用方可以将数据投影为 `()`，不另行维护状态枚举。

执行前将就绪目标捕获为拥有数据的 `Execution` 请求，随后释放对界面的借用。暂存携带文件快照、行选区计划或冲突结果；丢弃、冲突解决和贮藏预览携带对应快照；历史分页携带已解析的历史列表。纯界面操作在已经验证的当前视图中修改状态。键盘暂存与底部冲突操作复用同一个解析与执行入口。

捕获请求以后移动光标不会改变请求里的文件。仓库归属、命令草稿中的选区版本，以及写入前的文件和索引新鲜度校验继续保留；拥有目标不意味着跳过这些校验。

## 解析与执行

菜单、参数补全、回车、鼠标点击和直接执行统一使用 `resolve_command`；`command_availability` 只保留结果的可见性投影。功能开关、目标范围与动作条件依次检查，最终状态由互斥枚举表达：

| 状态 | 普通菜单与上下文搜索 | 主动全局搜索 | 执行 |
| --- | --- | --- | --- |
| 功能关闭或错误页不支持 | 隐藏 | 隐藏 | 拒绝 |
| 目标不属于当前场景 | 隐藏 | 灰色，说明需要的场景 | 拒绝，保留草稿 |
| 场景相关，但条件不足 | 灰色，说明缺少的条件 | 灰色，说明缺少的条件 | 拒绝，保留草稿 |
| 就绪 | 正常显示 | 正常显示 | 执行动作或进入预览确认 |

空的全局命令栏与带锁定前缀的上下文命令栏用于浏览当前场景。主动输入非空全局查询才揭示其它场景的命令：在子视图用 `//` 切到全局后输入，例如 `//repo log select`。输入范围显式传给公共可见性规则；命令自己不决定灰色或隐藏。

目标超出范围包括：文件列表没有差异选区，历史差异不提供工作区修改目标，普通差异没有冲突目标。条件不足包括：空历史没有提交、已到历史末尾、全选超过数量限制、当前冲突没有可撤销操作、所选文件没有改动、空文件列表尚无可复制路径。关闭 AI 或实验性功能后，相关命令在全局搜索中也不会出现。

参数列表始终按当前场景筛选。超出范围的命令即使在全局搜索中可见，也不会打开无法使用的参数列表；相关但不可用的选项继续置灰并显示原因。

命令草稿记录仓库路径和可复用的选中数据。列表刷新或排序后，已输入的文件路径命令仍指向打开命令时捕获的文件。丢弃选区还会在执行前核对预览版本和选区，确认后由 Git 操作层重新核对文件和索引快照。

## 可见性统一涉及的命令

这些命令原先在无关场景仍置灰，现在普通菜单隐藏、全局搜索置灰：

- `/repo diff stage`、`unstage`：需要工作区文件或差异。
- `/repo branch filter`：需要分支列表。
- `/repo log more`：需要提交历史列表；列表已到末尾时仍保留灰色入口。
- `/repo log parent`：需要提交详情；普通单父提交仍保留灰色入口并说明需要合并提交。
- `/repo stash scope`：需要贮藏详情。
- `/repo files diff`：需要文件浏览；浏览中选中无改动条目时置灰。
- `/repo compose` 的重新生成、说明编辑、排序、拆分、合并、移动、执行子命令：需要编排页面；生成中或重排已到首尾等条件不足时置灰。入口 `/repo compose` 仍可从仓库打开。

这些命令原先在其它场景完全隐藏，现在可通过全局查询找到，并显示不可用原因：

- `/repo log select`、`select all`、`select clear`、`cherry-pick`、`revert`。
- `/repo diff select`、`discard`、`discard-file`，以及整个 `conflict` 命令组。
- `/repo files mode`、`layout`、`/copy path`、不受当前场景支持的 `/search`。
- 暂存与未暂存子视图中属于另一组的暂存、取消暂存或丢弃操作。

`/copy path` 在文件列表、文件浏览或历史差异暂时没有选中文件时保留灰色入口；离开文件场景后按超出范围处理。

全局设置继续保持全局能力，例如差异布局、文件树布局、换行和显示范围配置，无需先打开差异才可以修改。

## 扩展方式

新增命令时先复用现有目标，再补充操作自身的状态条件。新增视图时从当前焦点或选中项提供同一种目标，文件级命令即可复用。只有目标的数据、身份或操作边界确实不同时，才增加目标类型。
